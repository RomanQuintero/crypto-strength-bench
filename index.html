Benchmark methodology & machine information +

CPU: each candidate is generated and UTF-8 encoded, then evaluated through native Web Crypto. Timing uses performance.now() inside one worker. SHA-256 warms up with 256 evaluations; PBKDF2 with 8. Timed work includes generation, encoding, async/native API overhead, digest consumption and progress reporting. PBKDF2 also includes key import, a fixed synthetic salt and a 256-bit derived output. Initialization and warm-up are excluded.

GPU: a CUDA process generates the same alphanumeric candidates on device, computes SHA-256, and writes every complete digest. Batches contain up to 262,144 candidates. Steady-state timing includes kernel launches, event synchronization, digest copies to CPU and checksum. CUDA events measure kernel-only time separately. Three batches warm up before timing. Complete request timing includes process startup, context initialization, known-vector tests, allocation, warm-up and sampled CPU verification. CPU/GPU checksums must agree for completed identical workloads.

Runs stop after the requested evaluations or roughly 15 seconds (per evaluation on CPU; per batch on GPU). Cancellation terminates the worker or the CUDA process and discards partial measurements. Short runs can be noisy; repeat measurements. Headline rates measure application implementations, not peak hardware. Estimates assume sustained rate and identical candidate cost; changing length does not rerun the benchmark. Search-space integers use BigInt; times use base-10 logarithms. PBKDF2 and tiny secret recovery remain CPU features.
